# سيناريوهات تحقق الخلفية — Phase 2A

هذه سيناريوهات مراجعة محلية قبل النشر، وليست بيانات إنتاج أو نسبًا افتراضية. كل نسبة في السيناريو تمثل قيمة أدخلها المشرف يدويًا في صف الكود.

## الكتالوج

1. يقبل منتج مكمل رياضي ومتغيراته.
2. يقبل منتج إكسسوار لياقة بأبعاد اختيارية مثل اللون أو المقاس.
3. لا تُنشأ فئة أو seed أو سيناريو خارج المكملات الرياضية وإكسسوارات اللياقة.

## تحكم المشرف في النسب

1. كود A بإعداد المشرف `customer=8`, `commission=5` يحسب كل نسبة بشكل مستقل.
2. كود B بإعداد المشرف `customer=12`, `commission=9` يستخدم القيم الجديدة دون أي افتراض برمجي.
3. كود C بإعداد المشرف `customer=20`, `commission=0` يمنح خصمًا ولا ينشئ عمولة.
4. كود عمولة فقط مثل `customer=0`, `commission=6` صالح عند ربطه برياضي.
5. يرفض الكود إذا كانت النسبتان صفرًا، أو تجاوزت إحداهما 100، أو كانت العمولة موجبة بلا رياضي.
6. تغيير نسب الكود لا يغير لقطة طلب أو عمولة سابقة.

## نطاق الكود

1. `global`: المجموع المؤهل يساوي مجموع كل الأسطر.
2. `category`: يؤهل فقط الأسطر التي تنتمي إلى فئة مستهدفة، حتى لو احتوى الطلب منتجات أخرى.
3. `product`: يؤهل فقط المنتجات المستهدفة.
4. يرفض كود category/product النشط إذا لم تكن له أهداف.
5. يرفض إدخال هدف منتج لكود category والعكس.
6. الحد الأدنى يقارن بالمجموع المؤهل لا بمجموع العناصر غير المطابقة.

## مثال حساب غير ثابت

إذا ضبط المشرف كودًا على خصم عميل 8% وعمولة رياضي 5%، وكان مجموع الطلب 500 د.ل لكن المنتجات المؤهلة 300 د.ل:

- الخصم: `300 × 8% = 24 د.ل`.
- إجمالي العميل: `500 - 24 = 476 د.ل`.
- العمولة: `300 × 5% = 15 د.ل`، قبل خصم العميل.

يجب تكرار الاختبار بنسب أخرى يختارها المشرف لإثبات عدم وجود نسبة ثابتة في الدالة.

## الأمان والتزامن والتاريخ

1. لا يستطيع anon قراءة جداول الأكواد أو نطاقاتها أو الرياضيين أو العمولات.
2. لا يستطيع العميل إدخال سعر أو خصم أو عمولة في `submit_order`.
3. محاولتا شراء آخر وحدة تؤديان إلى نجاح معاملة واحدة فقط.
4. إلغاء الطلب يعيد المخزون ويسجل حركة ويحوّل العمولة إلى `void`.
5. التسليم يعتمد العمولة، والصرف يحول عدة عمولات معتمدة لرياضي واحد إلى `paid`.
6. لا تتغير المبالغ التاريخية عند تعديل الكود أو تعطيله لاحقًا.
